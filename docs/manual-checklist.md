# ateam 手工核对清单

代码已通过语法检查和一次性端到端模拟（命令行层面：派发、打回、依赖唤醒、提问答复、掉线接手、连续打回挂起、服务重启重连、按路径提交）。以下是需要你在真实环境里核对的部分。

1. [ ] 在 agent-team 目录运行 `npm link` 后，在任意目录能运行 `ateam help`
2. [ ] 两份 skill 已软链（见 README「安装」）；agent 能识别 `ateam-worker`，Claude Code 能识别 `ateam-lead`
3. [ ] 在一个真实项目（git 仓库）根目录运行 `ateam serve`，浏览器打开 <http://127.0.0.1:7700> 能看到看板；项目的 `.gitignore` 里多了 `.ateam/`
4. [ ] 开 2 个 agent 窗口（前端、后端），对它们说「使用 ateam-worker skill，角色 frontend / backend」；加入后看板顶部显示 2 个在线 worker
5. [ ] 对 Claude Code 说「使用 ateam-lead skill，需求是……」（选一个小需求），能看到它拆任务、派发，两个 worker 并行开发
6. [ ] 看板上能看到进度笔记实时增加；review 的打回和通过出现在任务时间线里；需求页的 review 统计（review 次数、一次通过率、打回次数）正确
7. [ ] 关掉一个 agent 窗口（模拟 token 用完），约 15 分钟后看板显示该 worker 掉线（灰色）、任务退回「待领取」并带「接手」标记；开新窗口加入后，它收到「⚠ 接手任务」并在已有改动上继续
8. [ ] 收到 Claude Code 的最终汇报；看板上该需求顶部显示汇报内容（标题、列表、代码块渲染正常）
9. [ ] 看板在深色模式和窄屏（手机宽度）下显示正常；点开任务卡片的详情抽屉，3 秒刷新后抽屉不关闭、滚动位置不跳；按 Esc 能关闭
10. [ ] worker 在 `ateam wait` 挂起期间（最多 90 秒）没有被工具超时打断

## 演示卡

前提：项目里有一份按格式写好并已提交的 `docs/demo/<名字>.md`，leader 已建好演示需求和演示卡，至少开着一个 test worker。

1. [ ] 有普通任务在进行中、待 review 或等待答复时，演示卡的「开始演示」按钮是灰的，鼠标悬停写明是哪张卡；没有空闲的 test worker 时同样置灰并说明
2. [ ] 条件满足后点「开始演示」：看板顶部出现「等待 worker 开始演示」横幅，test worker 很快领走，横幅变成「演示中」
3. [ ] 演示中其他角色的 worker 领不到新任务（它们的输出写着「正在演示……演示结束后继续派发」），待领取的卡留在原处
4. [ ] test worker 在**前台** Chrome 里按脚本顺序操作，每步按脚本停留；看板演示卡和横幅上的「第 N/M 步：……」随之更新，计时每秒在走
5. [ ] 演示中点「停止演示」：横幅立即消失，派发恢复；worker 停在当前页面，不清理数据，只写经验并提交
6. [ ] 完整跑完一次：worker 执行脚本的清理段，只删「演示-」开头且标了【清理】的数据；脚本「## 经验」段多了内容，git log 里有 `[T?] 演示经验：…` 提交，提交只包含这一个文件
7. [ ] 演示卡回到「待演示」，详情抽屉里的演示记录多了一行（开始时间、演示者、跑完 / 叫停、说明、经验提交号）；再次开始演示，worker 收到的脚本里带着上次的经验
8. [ ] 点开始后没有 test worker 来领（比如先关掉 test 窗口）：约 2 分钟后自动撤回，横幅消失，派发恢复
9. [ ] 手动让 worker 改动脚本「## 演示步骤」段再 `ateam demo save`：被拒绝，提示只能改经验段，仓库里没有新提交
10. [ ] 演示需求在需求列表里带「演示」标记，不显示进度条；不出现在「待你验收」；普通需求的进度、review 统计不受演示卡影响
11. [ ] 演示中，演示卡下方出现提词区：小字「第 N/M 步 · 这一步做什么」和计时，大字是脚本里这一步的「讲解：」（没写讲解的步骤显示这一步做什么），下面是「下一步：……」；顶部横幅同步显示一行
12. [ ] 点「全屏提词」整页只显示提词，worker 每走一步自动更新；按 Esc 或点「退出全屏」返回；演示结束后全屏自动关闭
