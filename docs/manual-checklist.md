# ateam 手工核对清单

代码已通过语法检查和一次性端到端模拟（命令行层面：派发、打回、依赖唤醒、提问答复、掉线接手、连续打回挂起、服务重启重连、按路径提交）。以下是需要你在真实环境里核对的部分，按功能分组，新加的条目放进对应的组里。

## 基本流程

1. [ ] 在 agent-team 目录运行 `npm link` 后，在任意目录能运行 `ateam help`
2. [ ] 两份 skill 已软链（见 README「安装」）；agent 能识别 `ateam-worker`，Claude Code 能识别 `ateam-lead`
3. [ ] 在一个真实项目（git 仓库）根目录运行 `ateam serve`，浏览器打开 <http://127.0.0.1:7700> 能看到看板；项目的 `.gitignore` 里多了 `.ateam/`
4. [ ] 开 2 个 agent 窗口（前端、后端），对它们说「使用 ateam-worker skill，角色 frontend / backend」；加入后看板顶部显示 2 个在线 worker
5. [ ] 对 Claude Code 说「使用 ateam-lead skill，需求是……」（选一个小需求），能看到它拆任务、派发，两个 worker 并行开发
6. [ ] 看板上能看到进度笔记实时增加；review 的打回和通过出现在任务时间线里；需求页的 review 统计（review 次数、一次通过率、打回次数）正确
7. [ ] 关掉一个 agent 窗口（模拟 token 用完），约 15 分钟后看板显示该 worker 掉线（灰色）、任务退回「待领取」并带「接手」标记；开新窗口加入后，它收到「⚠ 接手任务」并在已有改动上继续
8. [ ] 收到 Claude Code 的最终汇报；看板上该需求顶部显示汇报内容（标题、列表、代码块渲染正常）
9. [ ] 看板在深色模式和窄屏（手机宽度）下显示正常；点开任务卡片的详情抽屉，3 秒刷新后抽屉不关闭、滚动位置不跳；按 Esc 能关闭
10. [ ] worker 在 `ateam wait` 挂起期间（最多 90 秒）没有被工具超时打断

## 演播卡

前提：项目里有一份按格式写好并已提交的 `docs/demo/<名字>.md`，leader 已建好演播需求和演播卡，至少开着一个 test worker。

1. [ ] 有普通任务在进行中、待 review 或等待答复时，演播卡的「开始演播」按钮是灰的，鼠标悬停写明是哪张卡；没有空闲的 test worker 时同样置灰并说明
2. [ ] 条件满足后点「开始演播」：看板顶部出现「等待 worker 开始演播」横幅，test worker 很快领走，横幅变成「演播中」
3. [ ] 演播中其他角色的 worker 领不到新任务（它们的输出写着「正在演播……演播结束后继续派发」），待领取的卡留在原处
4. [ ] test worker 在**前台** Chrome 里按脚本顺序操作，每步按脚本停留；看板演播卡和横幅上的「第 N/M 步：……」随之更新，计时每秒在走
5. [ ] 演播中点「停止演播」：横幅立即消失，派发恢复；worker 停在当前页面，不清理数据，只写操作记录并提交
6. [ ] 完整跑完一次：worker 执行脚本的清理段，只删「演示-」开头且标了【清理】的数据；脚本「## 操作记录」段有更新，git log 里有 `[T?] 操作记录：…` 提交，提交只包含这一个文件
7. [ ] 演播卡回到「待演播」，详情抽屉里的演播记录多了一行（开始时间、演播者、跑完 / 叫停、说明、操作记录提交号）；再次开始演播，worker 收到的脚本里带着上次的操作记录
8. [ ] 点开始后没有 test worker 来领（比如先关掉 test 窗口）：约 2 分钟后自动撤回，横幅消失，派发恢复
9. [ ] 手动让 worker 改动脚本「## 演示步骤」段再 `ateam demo save`：被拒绝，提示只能改「## 操作记录」段，仓库里没有新提交
10. [ ] 演播需求在需求列表里带「演播」标记，不显示进度条；不出现在「待验收」；普通需求的进度、review 统计不受演播卡影响
11. [ ] 演播中，演播卡下方出现提词区：小字「第 N/M 步 · 这一步做什么」和计时，大字是脚本里这一步的「讲解：」（没写讲解的步骤显示这一步做什么），下面是「下一步：……」；顶部横幅同步显示一行
12. [ ] 点「弹出提词窗」弹出一个深色字幕小窗，停在屏幕最下方：大字讲解、上方第几步和计时、下方下一步，worker 每走一步自动更新；小窗可拖到第二块屏幕，点「全屏」放大；演播结束后小窗显示「已结束」，下次开始自动接上
13. [ ] 新建的演播卡显示「未预演」，只有「开始预演」按钮；预演跑完变「已预演」，出现「开始演播」「重新预演」
14. [ ] 预演结束后，脚本「## 操作记录」段每步都有一条（怎么找元素、做什么、等到什么，关键步骤标【核对】），卡详情里能看到这一段
15. [ ] 演播明显比预演快：worker 不逐步截图，只在【核对】步截图
16. [ ] 故意改坏一步（比如改了按钮文字）：演播时那一步提词区出现「慢档」，worker 走通后继续，收尾时操作记录里那一步被更新；运行记录里写着「慢档：第 N 步」
17. [ ] 普通任务通过 review 后，已预演的演播卡显示「页面可能有变动」；重新预演跑完后消失
18. [ ] 预演时 worker 没录全（某步没有 ```cua 动作块、或缺开头的「视口：」行）就 `demo end`：被拒绝并列出缺的步骤；录全后才变「已预演」；右侧步骤大纲里没录的步骤标「未录」
19. [ ] 演播时 worker 每步用 cua_execute 一段一次回放，不逐步截图，只在【核对】步带截图；整体比预演明显快
20. [—] 把浏览器窗口改小再开始演播：worker 先运行 `ateam demo viewport` 把窗口调回去、截图核对后继续；屏幕放不下时才停住，提示预演时和现在的视口尺寸（已作废：视口改由 worker 用浏览器工具调整，见 33）
21. [—] 已预演的演播卡上有「ateam demo viewport T?」可复制命令；把窗口拖小后在终端运行它，视口回到预演时的尺寸（Chrome 没开「允许 Apple 事件中的 JavaScript」时，按提示用 --now 或手动 osascript 命令）（已作废：视口改由 worker 用浏览器工具调整，见 33）
22. [ ] 未预演的卡只有「开始预演」，点了直接开始、不弹选择窗；「重新预演」也不弹窗
23. [ ] 已预演的卡点「开始演播」弹出窗口，三个选项可选；「只演选中的几步」一步不选时确认按钮不可点
24. [ ] 选「从第 12 步开始」：worker 不执行准备段、不删上一场的演示数据，从第 12 步开始做；提词显示「第 12/21 步（本场 1/10）」；大纲里 1–11 步变灰标「本场跳过」，进度条里是虚格
25. [ ] 上一场在第 12 步停住（中断或叫停），再点「开始演播」，默认选中「从第 12 步继续」
26. [ ] 选「只演 3、5、7 步」：只做这三步；跑完收尾说明写明不清理，演示数据还在
27. [ ] 从中间开始一直跑到最后一步并跑完：执行清理，整场的演示数据被删掉
28. [ ] 运行记录表显示这一场演了哪几步（「第 12–21 步」/「选 3 步：3、5、7」）
29. [ ] 演播中点「暂停」：worker 做完当前这一步后停住，浏览器停在当前页面；卡、横幅、提词小窗显示「已暂停」，时间线有「暂停」
30. [ ] 暂停超过 1 分钟：worker 窗口里 `ateam demo step … --round N` 原样重复运行等待，没有操作浏览器，也没被判掉线
31. [ ] 点「继续」：worker 几秒内接着做下一步；提词切到下一步
32. [ ] 暂停中点「停止演播」：worker 收到已叫停，进入收尾
33. [—] 设置 →「演播视口」选 1920×1080 后开始预演：worker 先把浏览器调到 1920×1080（页面里 innerWidth/innerHeight），操作记录开头写「视口：1920x1080」；再把设置改回 1600×800，这张卡开始演播时 worker 仍按 1920×1080 调（已作废：视口改在开始预演时选，见 37）
34. [ ] 旧格式（```cua 坐标）的演播卡：「开始演播」不可点，卡上提示「操作记录是旧格式，请重新预演」；重新预演后操作记录变成「工具 / ```actions / 预期」格式，之后能演播
35. [ ] 预演时故意漏写某步的「预期：」行，`ateam demo end` 被拒并列出缺哪一步
36. [ ] 演播中把某一步要点的按钮文字改掉（或删掉对应数据），让预期对不上：worker 这一步切慢档、自己走通，并把新的动作块和预期写回操作记录
37. [ ] 点「开始预演」先弹出视口选择：没预演过的卡默认选上次预演选的尺寸，预演过的卡默认选它录的尺寸（标「上次」）；选 1920×1080 开始，worker 把浏览器调到 1920×1080，操作记录开头写「视口：1920x1080」；之后这张卡开始演播不再问，worker 仍按 1920×1080 调；自定义填 `1600*800`、`100x100` 时「开始预演」按钮不可点；设置页里不再有「演播」一组
38. [ ] 已预演过的卡选另一个视口重新预演：worker 领到后脚本的「## 操作记录」变空（其他三段不变）；worker 把开头视口写成旧尺寸时 `demo end` 被拒并提示要改成这次选的尺寸；跑完 `demo save` 后只剩新记录
39. [ ] 重新预演中途叫停（或 worker `--stuck`、或点「结束收尾」）：「## 操作记录」还原成上一版，git 里没有新提交，卡仍是「已预演」，可以直接开始演播
40. [ ] 演播需求页右键（触屏长按）一张演播卡：出现和看板卡片一样的菜单；「作废…」弹确认框，确认后演播卡进「已作废」、不能再开始；演播中的卡还有「收回换人…」。左侧右键演播需求「作废需求…」会连带作废它的演播卡，需求从 demos/ 移到 archive/

## 需求作废

1. [ ] leader 不带 `--user-approved` 运行 `ateam job cancel J?`：被拒绝，列出将被作废的卡（不含已通过的卡）
2. [ ] 带 `--user-approved` 后：需求移到左侧「已作废」分组，需求页显示作废时间和原因；已通过的卡仍在「已通过」列，其余卡在「已作废」列表里
3. [ ] 正在做其中一张卡的 worker 下次调用 ateam 时收到停手通知，还原改动后去领别的任务
4. [ ] 作废后 `ateam task add --job J?` / `ateam job edit J?` 被拒绝；`ateam status` 不再列出该需求

## 暂停领取

1. [ ] 卡详情「派发顺序」下面有「暂停领取」：点了之后卡上标「暂停领取」，空闲的同角色 worker 不领它；点「恢复领取」后照常派发
2. [ ] 需求页右上概览卡，鼠标移入后右上角出现「暂停领取」（整个需求）：需求下待领取的卡都标「暂停领取」、不派发，之后新加的卡也不派发；正在做的卡照常做完；点「恢复领取」后恢复
3. [ ] leader `ateam task hold T? "原因"` / `ateam job hold J? "原因"` 与看板效果一致，`--off` 恢复；`ateam status` 里显示「暂停领取」
4. [ ] 整个需求暂停领取时，左侧需求项（展开和收窄的需求栏）显示和待领取列一样的斜纹，状态处标「已暂停」；选中时斜纹仍在；恢复领取后恢复原样

## 派发与 review

1. [ ] 两张卡改同一个目录，一张有人在做：另一张不派，卡片计时处写「等 T? 交」，同角色空闲 worker 的等待说明里写原因；那张提交后另一张照常派出
2. [ ] leader `ateam show T?`（有提交的卡）：开头有 review 摘要，列出改了的文件、+/− 行数、「新文件」、不在任务路径里的文件标 ⚠
3. [ ] leader 对进行中的卡 `ateam task edit T? --desc-file ... --accept ...`：成功，输出写明已通知 worker；worker 下一次 progress / wait / submit 收到「leader 修改了这张卡的描述、验收标准，以卡片最新内容为准」及新内容；看板卡片显示新描述，时间线「修改 · 已通知」；改进行中卡的 --role 或 --after 被拒
4. [ ] `ateam task add ... --paths a --paths b --after T1 --after T2`：路径是 a、b，依赖是 T1、T2；`--title x --title y` 报错「写了两遍」
5. [ ] 新卡和一个暂停领取的需求里的卡路径重叠：「⚠ 路径重叠」里那张卡标「暂停领取中」，建议给暂停的卡加 --after 新卡，而不是反过来

## 无 leader 模式

1. [ ] 点顶部 leader 芯片 → leader 标签页最上面的 leader 卡片点「下线」：leader 芯片变「无 leader 模式」；某 worker 提问（或提交）后，`wait` 直接给它一张没有依赖、不改同一批文件的新卡，末尾写「你转做前放下的卡：T?」，看板上原卡标「转做 T?」（T? 是 worker 新领的卡）；依赖待 review 卡的卡、和放下的卡改同一批文件的卡都不派
2. [ ] 无 leader 模式下 leader 执行任意命令（`ateam status` 即可；后台 `watch --follow` 不算）：自动退出，leader 收到 `leader_back` 事件列出积压；答复 / 打回放下的卡后，卡标「留给 xx」，原 worker 做完手上的卡后收到「# 转做前放下的任务回来了」；原 worker 掉线时其他 worker 能接手
3. [ ] 设置里打开「leader 掉线时自动进入」并把时间改成 1 分钟：关掉 leader 的后台监听、1 分钟不操作，自动进入无 leader 模式；leader 重新挂上 `watch --follow` 后自动退出；关掉开关时不会自动进入；手动「下线」时只挂监听不会退出，执行命令才退出

## 项目规则

1. [ ] 规则文件没有任何 `## ` 小标题时：各角色领卡收到的规则和文件全文一致；超过 8 条时 `ateam rules` 末尾提醒「还没按角色分段」
2. [ ] 分段后（`## ALL` / `## backend` / `## frontend, test`）：test 卡收到 ALL 段和 frontend, test 段，收不到 backend 段；`ateam rules --role test` 显示同样内容
3. [ ] `ateam rules add "…" --role test` 不带 `--user-approved` 被拒，说明写「将在 test 段加一条」；带上后加到 test 段末尾（没有 test 段就新建）；`set --file` 不带授权被拒并列出各段条数变化
4. [ ] 看板 使用说明 →「项目规则」：编辑框下方「预览 <角色> 会收到」随输入实时变化；保存不需要额外确认
5. [ ] 写一段 `## 全员`：`ateam rules` 和看板预览上方都提示「这些段目前没有角色会收到：全员」
6. [ ] 规则里写一段 `## leader`（`## lead` 也认）：worker 领卡收不到这一段；看板和 `ateam rules` 不提示「没有角色会收到」；`ateam status` 末尾显示这一段；leader `ateam show T?`（有提交的卡）在 review 摘要后也显示；`ateam join --role leader` 被拒

7. [ ] 在 worker 页点某个 worker 的「下线」：名字那一行不再挤着折行，下面单独出现一条确认栏「让 xx 怎么下线？」（最后一个时有说明），按钮在右边

## 直接回复 worker

1. [ ] 等待答复的卡：打开详情（或右键「回复提问…」，会滚到并聚焦输入框），回复框在详情最下面、时间线后面，样式是一个整体的输入框（提示和发送按钮在框内底部，输入时框会跟着长高）；写字时页面刷新不丢字、不丢焦点；⌘↩ 或「发送」后卡回到进行中，worker 收到以「# 答复 T?（用户直接答复…）」开头的输出，leader 收到 user_reply 事件且不再重复答复；时间线里出现「答复 · 你」
2. [ ] 进行中、返工中的卡：回复框变成「给 worker 留言」，发送后 worker 下一次 progress / wait / submit 看到「补充说明（用户直接说）…」，leader 收到 user_reply 事件
3. [ ] 待 review 的卡：详情最下面是「给 leader 和 worker 留言」，发送后 leader 收到 user_reply 事件（提示 review 时按它核对）；leader 打回后，worker 收到的打回意见后面附着「补充说明（用户直接说）…」
4. [ ] 按 `docs/worker-hook-setup.md` 启用 hook 后：worker 正在连续干活（中途不调用 ateam）时在看板留言，它在下一个工具调用结束后就看到「# ateam 补充说明」并照做；同一条留言不会在之后的工具调用后重复出现，下一次 progress / wait / submit 还会再带一遍
5. [ ] 启用 hook 后：两个 worker 在同一目录干活，给其中一张卡留言，只有拿着这张卡的 worker 收到；在没有 ateam 的项目里用 DSH 不受影响；停掉 ateam 服务时 worker 照常干活，不报错
6. [ ] 未启用 hook，或平台运行了 hook 但没把内容交给模型：留言仍在 worker 下一次 progress / wait / submit 时送达，和原来一样
