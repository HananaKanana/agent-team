# 演播卡：从第 N 步开始、只演选中的几步

日期：2026-10-25
状态：待用户审阅
前置：`2026-10-24-demo-cards-design.md`（演播卡）、`2026-10-24-rehearsal-design.md`（预演与演播）

## 1. 为什么要做

演播现在只能从第 1 步完整跑到最后。实际用的时候：

- 上一场在第 12 步断了（走不通停住，或被叫停），想接着从第 12 步往下演，不想从头再来一遍；
- 客户只想看其中一段，只演那几步。

## 2. 目标、非目标、反目标

**目标**
- 已预演过的演播卡，开始**演播**时可以选「从第 N 步开始」或「只演勾选的几步」。
- 上一场中断或叫停时，默认给出「从第 N 步继续」（N 是上一场停下的那一步）。
- 进度、提词、步骤大纲、运行记录都按这一场选中的步骤显示，步骤编号保持原编号。

**非目标**
- 预演不能跳步：预演必须从头完整走，才能录全操作记录。
- 不自动补跑被跳过的步骤，不自动造数据。
- 不加快档 / 慢档的手动开关（用户确认保持自动切换）。

**反目标**
- worker 在部分演播开始前按「## 准备」段把上一场留下的「演示-」数据清掉——那正是接着演要用的数据。
- 只演了中间几步就执行「## 清理」，把下一场要接着用的数据删了。

## 3. 用户已定下的事

| 事项 | 决定 |
|---|---|
| 谁能选步骤 | 只有演播能选；预演一律完整跑 |
| 跳过的步骤留下的数据和页面状态 | 用户自己保证（典型：上一场断了，数据还在），worker 不补跑 |
| 演到一半发现缺数据 | 按「对不上」处理：先慢档，走不通就停住，说明里写缺了什么 |
| 清理 | 这一场跑到了最后一步（且跑完）才执行「## 清理」，清理整场的演示数据；没跑到最后一步不清理 |
| 快档 / 慢档 | 保持 worker 自动切换，不加开关 |
| 在哪里选 | 方案 B：点「开始演播」弹出窗口来选 |

## 4. 考虑过的做法

后台只有一种合理做法：开始演播时把「这一场演哪几步」一起交给服务，记在这一场的运行记录上，worker 的指令、进度、收尾都按它来。要定的是看板上怎么选：

- **A. 在右侧「脚本步骤」大纲里直接勾选**：边看步骤边选，不多开窗口；但大纲同时承担「进行中显示进度」和「待演播时勾选」两种用途。
- **B. 点「开始演播」弹出窗口选（用户选择）**：大纲保持只读，每次开演前都过一眼确认；代价是每次演播多点一下，步骤列表在窗口里重复出现一次。

## 5. 设计

### 5.1 数据

- 一场运行记录（`run`）新增可选字段 `steps`：这一场选中的步骤编号，升序、去重的整数数组。没有这个字段 = 完整演播（老数据同样按完整处理）。
- 一场运行记录新增 `lastStep`：这一场最后报到的步骤编号（worker 每次 `demo step` 时更新）。用来给下一场默认「从第 N 步继续」。
- `startDemo(taskId, mode, steps)`：
  - `mode = 'rehearsal'` 时传了 `steps` → 拒绝（「预演要从头完整走，不能选步骤」）。
  - `steps` 必须非空，每个都是 1…脚本总步数之间的整数；总步数由服务读脚本得出（脚本读不到时拒绝选步骤，提示原因）。
  - 选中了全部步骤时等同完整演播，不记 `steps`。
  - 和 `pendingMode` 一样先挂在卡上，worker 领取时写进 `run.steps`。

### 5.2 worker 指令（`# 演播` 输出）

完整演播时不变。部分演播时，规则开头多一段，写清：

- 这一场只演哪几步：「第 12–21 步」或「第 3、5、7、8 步」；没列出的步骤**完全不做**，也不 `demo step`。
- **不执行「## 准备」段**（那里会清掉上一场留下的演示数据，而这些数据正是接着演要用的）；只做视口核对，并截图确认当前页面能接上第一步。
- 跳过的步骤留下的数据和页面由用户保证。某一步要用的数据不在、页面接不上 → 按对不上处理：这一步切慢档；慢档也走不通就停住，`--stuck` 说明里写清缺了什么。
- `demo step` 照样用原编号和总步数（比如 `12/21`）。
- 选中的最后一步跑完就 `demo end`。

服务端：部分演播时 `demo step` 报的编号不在选中的步骤里 → 拒绝，并告诉 worker 这一场要演哪几步。

### 5.3 收尾与清理

- 跑完（`done`）且选中的步骤**包含最后一步** → 收尾说明照旧，执行「## 清理」，清理整场的演示数据（名称以「演示-」开头、标了【数据：清理】的数据）；有的数据本来就不存在，跳过即可，不算出错。
- 跑完但**没包含最后一步** → 收尾说明写「这一场只演了中间几步，不清理，数据留给下一场接着用」。
- 中断 / 叫停 → 照旧不清理。
- 走了慢档的步骤照旧更新操作记录。部分演播不改变「已预演」状态；中断照旧标「页面可能有变动」。

### 5.4 看板

**开始演播的弹窗**（只在点「开始演播」时出现；「开始预演」「重新预演」照旧直接开始，不弹窗）：

- 三个选项（单选）：
  1. **从头完整演播**
  2. **从第 N 步开始**：下拉选择步骤（显示「编号 + 这一步做什么」），从这步演到最后一步。
  3. **只演选中的几步**：展开步骤列表，每步一个复选框，可以「全选 / 全不选」。
- 默认选中：上一场（不论预演还是演播）是中断或叫停、且有 `lastStep` → 选项 2，N = 上一场的 `lastStep`，选项文字写「从第 12 步继续（上一场停在这里）」；否则选项 1。
- 卡标了「页面可能有变动」时，弹窗里照样显示这条提醒。
- 确认按钮文字随选择变化：「开始演播」「从第 12 步开始演播（12–21）」「演播选中的 4 步」。一步都没选时不能点。
- 开不了的原因（有任务进行中等）照旧在弹窗里显示，不关窗口。

**进行中**：

- 提词区、提词小窗、悬浮窗：照旧显示「第 12/21 步」；部分演播时旁边加「本场 1/10」。
- 步骤进度条：没选中的步骤画成浅色虚格，只有选中的步骤算进度。
- 右侧步骤大纲：没选中的步骤变灰，并标「本场跳过」。

**事后**：

- 运行记录表多显示这一场演了哪几步（「第 12–21 步」/「选 4 步：3、5、7、8」）；完整演播不显示。
- 演播卡行的「上次 …」照旧。

### 5.5 命令行与说明

- `ateam demo start` 不新增（开始演播只在看板上点）。`ateam show` / `ateam status` 里演播卡的运行记录带上「第 x–y 步」。
- worker skill：主循环表 `# 演播` 一行补一句「部分演播只做列出的步骤，不执行准备段」。
- leader skill：演播卡一节补一句「演播可以从某一步开始或只演几步，在看板开始演播的弹窗里选」。
- 手工核对清单补几条（见第 7 节）。

## 6. 约束

- 沿用：零依赖、ESM、Node ≥ 18；不新写测试代码，scratchpad 一次性探测；看板交给用户手工核对。
- 老数据兼容：老的运行记录没有 `steps`、`lastStep`，按完整演播显示；没有 `lastStep` 时弹窗默认「从头完整演播」。

## 7. 手工核对清单（交给用户 / 测试任务）

1. 未预演的卡只有「开始预演」，不弹选择窗；「重新预演」也不弹窗。
2. 已预演的卡点「开始演播」弹窗，三个选项可选；一步不选时确认按钮不可点。
3. 选「从第 12 步开始」：worker 不执行准备段、不删上一场的演示数据，从第 12 步开始做；提词显示「第 12/21 步 · 本场 1/10」；大纲里 1–11 步变灰标「本场跳过」。
4. 上一场在第 12 步停住，再点「开始演播」，默认选中「从第 12 步继续」。
5. 选「只演 3、5、7 步」：只做这三步；跑完不执行清理，收尾说明写明不清理。
6. 从中间开始一直跑到最后一步并跑完：执行清理，整场的演示数据被删掉。
7. 运行记录表显示这一场演了哪几步。

## 9. 我替用户做的决定（请审阅时确认）

- 部分演播**不执行「## 准备」段**，只做视口核对和页面截图确认。（理由：准备段会清掉上一场的演示数据，和「接着演」冲突。）
- 「从第 N 步继续」的 N 取上一场最后报到的那一步（那一步可能只做了一半，所以从它重新开始，而不是从下一步）。
- 选中全部步骤等同完整演播。
- `demo step` 报了没选中的步骤会被拒绝。
- 部分演播的提词旁加「本场 x/y」，步骤编号仍用原编号。
- 不新增命令行的开始演播方式，选步骤只在看板上做。
