# 演播与浏览器工具解耦

日期：2026-10-26
状态：待用户审阅

## 为什么

现在的演播绑死在 WorkBuddy 的 `cua_execute` 上：
- 操作记录里录的是屏幕坐标；
- 为了让坐标点得准，要求视口一像素不差，于是有了一整套视口对齐：截图读尺寸、osascript 按「外框约 87 高」估算调窗口、`chrome-frame.json` 记外框、看板上的复制命令。这套很绕，Chrome 的「允许 Apple 事件中的 JavaScript」在用户机器上还开不了。

test worker 现在统一跑在 DeepSeek Harness 里，用 dsh-cdp 插件操作浏览器（`docs/dsh-cdp-guide/README.md`）。它能按元素点击、等文字出现、批量断言、改真实窗口大小。

## 用户已定下的事

- **ateam 不调用任何浏览器插件**。浏览器怎么操作是 worker 的事，用它手上的工具（现在是 dsh-cdp），换插件时 ateam 不用改。
- 现有演播卡**全部重新预演一遍**。
- 页面和预演不一致时要靠 worker 的智能补救，不能机械地点下去。

## 考虑过的做法

- **A. ateam 命令行直接调插件回放（否决）**：快档最快，但 ateam 会依赖 dsh-cdp，插件不能用或换插件时全部失效。
- **B. ateam 只定流程和记录结构，worker 用自己的工具执行（用户选择）**：ateam 与工具无关；动作块用当前工具的格式录，换工具就重新预演。

## 设计

### 视口

- 目标视口在看板「设置」里选（全局设置，存在服务端，和其他设置一样）：
  - 预设：`1280x720`、`1600x800`（默认）、`1920x1080`（1K）、`2560x1440`（2K）；
  - 也可以填自定义的「宽x高」。
- **预演**用当时的设置值，并在操作记录开头写一行「视口：宽x高」。
- **演播**用这张卡预演时记录的视口（预演和演播一致，页面布局才和录的时候一样）；记录里没有视口行时用当前设置值。
  - 改了设置不影响已经预演过的卡；想换尺寸就重新预演。
- 视口以页面里的 `innerWidth` / `innerHeight` 为准，不再靠截图读尺寸。
- 演播规则里的说法：「开始前用你的浏览器工具把页面视口调到 <宽>x<高>：先读页面的视口和窗口尺寸，按差值设真实窗口大小，再读一次确认。调不了（比如屏幕不够大）就停住报告。」目标尺寸由 ateam 写进指令。
- 只改页面视口、不改窗口的做法（比如 dsh-cdp 的 `resize`）**不能用**：页面会以为自己比窗口宽，内容溢出到窗口外。这一条写进 worker skill。
- 设置页在每个预设旁边注明：窗口要比视口再大一圈（标签栏、地址栏），选的尺寸超过屏幕时 worker 调不出来会停住。比如 MacBook 屏幕放不下 2K。

### 操作记录格式

每一步一个条目：

````
### 3. 新建装备
工具：dsh-cdp
```actions
<这一步的全部动作，用当前浏览器工具的格式，worker 能一次执行完>
```
预期：列表第一行出现「演示-现场气象站」，右上角提示「保存成功」
````

- **动作块**：代码块语言标记是 `actions`，内容 ateam 不解析。worker 自己定格式，以「下次演播能一次执行完」为准，比如一串 curl。按元素找目标（选择器、角色 + 名字），不录坐标。
- **工具行**：写明动作块是给哪个工具用的。
- **预期行**：这一步做完后页面上应该看到什么。要能用工具确定地核对，比如出现某段文字、某个元素存在或不存在、地址变了，不写「页面正常」这种看不出对错的话。
- **【核对】步骤**：预期照写。演播时 worker 除了核对预期，还要额外截一张图自己看一眼（同现在）。

**ateam 的检查**：预演跑完时（`demo end`），开头要有「视口：宽x高」行，每个演示步骤都要有「### N.」条目、`actions` 代码块和「预期：」行，缺了就拒绝，并列出缺哪些。动作块里写了什么不检查。

**旧记录**：带 ` ```cua ` 代码块、没有 `actions` 块的记录，视为「操作记录格式过期」：
- 卡上标「需要重新预演」，只能开始预演，不能开始演播；
- 看板和 `ateam demo` 的提示里写明原因。

### 演播规则（worker 指令）

- **快档**：每一步，先 `demo step` 报到；然后把这一步的动作块一次执行完，核对「预期」。
  - 对得上：下一步。
  - 对不上（动作报错、找不到元素、预期不符）：这一步切慢档。
- **慢档**：从这一步开头起，看页面、找元素、自己走通；把新的动作块和预期写回操作记录；`demo step` 加 `--slow`。
- **停住**：慢档也走不通，照旧 `demo end --stuck`。
- 暂停、叫停、部分演播、收尾规则都不变。
- 规则里只写通用说法（「你的浏览器工具」），不点插件的名字。

**预演规则**：
- 照脚本一步步走；
- 每走通一步，录下动作块、工具行、预期行；
- 预期要在录的时候实际核对一次，确认能对上；
- 开始前同样把视口调到设置里的尺寸，并在操作记录开头写「视口：宽x高」。

### 删掉的东西

- 命令 `ateam demo viewport`、`~/.ateam/chrome-frame.json` 及相关代码。
- 看板上的视口提示（osascript 命令、核对表达式、`--now` 说明）。
- `src/demo.js` 里 `cua` 动作块的解析和字段校验。
- 演播 / 预演规则里所有截图读视口、`cua_execute` 的说法。

### worker skill（ateam-worker）

演播一节改成用 DSH 的 browser-cdp：
- 用 `open` 开自己的标签页，演播全程用这个 tabId，收尾时 `close`；
- 调视口：`eval` 读 `innerWidth/innerHeight/outerWidth/outerHeight`，按差值用窗口控制脚本（`chrome-window.mjs set`）设真实窗口，再 `eval` 确认；
- 动作块写成一串 curl，一步一次 shell 调用执行完；
- 用 `wait` / `assert` 核对预期；
- 慢档用 `snapshot aria:true` 找元素。

### 看板

- 去掉视口提示块。
- 操作记录格式过期的演播卡：「开始演播」按钮不可用，旁边提示「操作记录是旧格式（坐标），请重新预演」。
- 运行记录、提词、暂停等不变。

## 约束

- 零依赖、ESM、Node ≥ 18；不新写测试代码，用 scratchpad 一次性探测；看板交用户手工核对。
- 演播脚本的「## 准备」「## 演示步骤」「## 清理」三段不变，提词不受影响。

## 我替用户做的决定（请审阅时确认）

- 视口预设是 1280x720 / 1600x800（默认）/ 1920x1080 / 2560x1440 加自定义；演播沿用这张卡预演时的视口。
- 动作块的代码块语言标记叫 `actions`，加「工具：」行和「预期：」行。
- 旧格式的卡只能预演、不能演播（而不是允许演播、出错再补救）。
- 窗口控制脚本 `chrome-window.mjs` 的路径和用法只写在 worker skill 里，ateam 代码里不出现。
