# 多人在同一个项目里用 ateam：看板放到专用分支同步

## 背景

ateam 原本设想的是一个人用：一台电脑、一个项目目录、一个 leader 和若干 worker。看板数据存在项目的 `.ateam/` 下：

- `board.json`：没结束的需求和卡、编号计数、设置。
- `archive/<需求编号>.json`：已验收、已作废的需求。
- `demos/<需求编号>.json`：演播需求。

默认会把 `.ateam/` 加进项目的 `.gitignore`。但 sp 把这一行删掉了，所以看板随代码一起提交到团队共用的仓库。

现在要支持几个人同时在同一个项目上用 ateam：每人在自己电脑上有一份代码，各自开 leader 和 worker。

## 现状下会出的问题（以 sp 为例）

1. **看板串在一起**：同事拉代码后，他的 ateam 会读到你的需求和卡，他的 worker 可能去领你待领取的卡，两边重复干活。
2. **编号撞车**：两人各自新建需求，都会得到 J117，`board.json` 和 `archive/J117.json` 推送时冲突。
3. **跨人改同一批文件没人管**：路径重叠保护只看本机的卡，两个人的 worker 改同一个文件，要到 git 推送时才撞上。
4. **main 历史全是看板提交**：sp 的 main 最近 200 个提交里，有 101 个是「chore(ateam): …」。

## 目标

- 每人一块自己的看板，互不干扰，推送永远不冲突。
- 能看到同事在做什么（需求、进行中的卡、谁在做、改哪些路径），延迟在一分钟左右。
- 跨人的路径冲突能在派卡前拦下，不只是事后提醒。
- 项目规则、测试报告模板仍然大家共用。
- main 里不再有看板提交。
- 一个人用的时候行为完全不变（不开启同步就和现在一样）。

## 不做的

- 不做中心服务器，不做跨机器统一派卡：worker 永远只领本机看板上的卡。
- 不能操作同事的卡（回复、验收、打回都不行），同事视图只读。
- 不做实时（秒级）同步，约一分钟的延迟可以接受。
- 不改编号格式。

## 考虑过的方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| 一：各管各的 | `.gitignore` 忽略看板数据，只提交规则和模板 | 不用写代码；但完全看不到对方，跨人冲突也没人管 |
| 二：每人一个目录 | `.ateam/boards/<名字>/` 随代码提交，编号加前缀 | 能互相看到；但要等对方推代码才能看到，看板提交仍混在 main 里，编号前缀要改代码和老数据 |
| 三：中心服务 | 一台服务器统一调度所有人的 worker | worker 分散在不同机器的代码目录里，提交、合并协调很复杂，容易出错 |
| **四：专用分支同步（选定）** | 每人的看板存在 `ateam/<名字>` 分支，后台每分钟自动推拉 | 不冲突、延迟一分钟、main 干净、不用额外服务器；工作量中等 |

选方案四。

## 可行性验证

在临时目录里搭了一个模拟远程，用两个克隆分别代表两个人：

- 工作区有未提交改动、暂存区也有内容时，用临时暂存区（`GIT_INDEX_FILE`）配合 `hash-object`、`update-index`、`write-tree`、`commit-tree`、`update-ref`，把看板写进分支并推送。结果：工作区和暂存区完全没被动，main 历史没有多出提交。
- 另一个克隆 `git fetch` 后，用 `git show <分支>:board.json` 直接读到内容，不需要检出，工作区里也不会出现这些文件。

## 设计

### 1. 分支和内容

- 远程分支：`ateam/<名字>`，比如 `ateam/kana`。
- 本地不建普通分支。自己的看板写在 `refs/ateam/self`，同事的拉到 `refs/ateam/peers/<名字>`。所以 `git branch` 看不到它们，worker 和 leader 的 git 操作也不受影响。
- 分支里的文件：

| 文件 | 内容 |
|---|---|
| `board.json`、`archive/`、`demos/` | 和本地 `.ateam/` 下的同名文件完全一样 |
| `sync.json` | `{ name, format, ateamVersion, updatedAt, host }`，同事视图和兼容判断用 |

- 不同步的：`runtime.json`（worker、事件）、端口、日志、`usage-daily.json`。
- 留在 main 的 `.ateam/`、大家共用的：`rules.md`、`test-template.md`、`.gitignore`。

### 2. 推（自己的看板 → 分支）

- 触发：看板保存后（persist 写完文件）防抖 30 秒；另外每 5 分钟兜底一次。
- 做法：
  1. 用临时暂存区，把 `.ateam/` 下要同步的文件和 `sync.json` 组成一棵树。
  2. 树和上一次相同就什么都不做。
  3. 不同就以 `refs/ateam/self` 为父提交，生成新提交，更新 `refs/ateam/self`。
  4. 执行 `git push <远程> refs/ateam/self:refs/heads/ateam/<名字>`。
- 历史是线性的，只追加不改写，不用强制推送。每次只新增改动过的文件，体积增长很小。
- 推送时不弹密码提示（`GIT_TERMINAL_PROMPT=0`），用本机已有的 git 凭据，和 leader 推 main 一样。

### 3. 拉（同事的看板 → 本地）

- 每 60 秒执行 `git fetch <远程> '+refs/heads/ateam/*:refs/ateam/peers/*'`。
- 自己那个分支跳过。
- 每个同事只读 `sync.json` 和 `board.json`：进行中的需求和卡都在 `board.json` 里，`archive/` 只在同事视图里查看已完成需求时才读。
- 结果放在内存里，供派卡检查和看板使用，不写进本地看板。

### 4. 名字

- 每台机器、每个项目设置一个同步名字，默认取 `git config user.name` 转成的短名字（只保留字母、数字和连字符）。
- 第一次推送前检查远程有没有同名分支。有的话，比对它的 `sync.json` 里的 `host`：
  - 不是这台机器：提示「名字已被占用」，同步不启动；
  - 是这台机器（换过目录、重装过）：接着用。
- 推送被拒、且不是快进（别人用了同一个名字）：同步暂停，看板提示。

### 5. 编号不改

- 每块看板的编号只需在自己的看板里不重复。本地的 J117、T1030 保持原样，现有数据不用迁移。
- 同事的需求和卡在界面上显示成 `wu·J117`、`wu·T88`。
- 代码里 6 处按「去掉首字母当数字」排序的写法不受影响。
- 代价：git 历史里两人可能都有「T1030 …」的提交，要靠提交人区分。

### 6. 跨人路径冲突

- **派卡时**：本机派卡前已经会检查「有没有别的 worker 正在做、路径重叠的卡」（`store.js` 的 `clashWith`）。把同事那边状态为 `working`、`asking` 的卡也加进这个检查。
  - 重叠就先不派。
  - 卡片计时处写「等 wu·T88 交」。
  - worker 的等待说明里写原因。
- **建卡时**：leader 新建或修改卡时，路径和同事未完成的卡重叠，在已有的「⚠ 路径重叠」提醒里列出（标明是谁的卡）。只提醒，不拦。
- **过期的占用**（我的决定）：同事超过 2 小时没有同步（电脑关了、服务停了），他的卡只在建卡时提醒、不再拦派卡，免得一台关掉的电脑把你的卡永远卡住。看板上标「wu 已 3 小时未同步」。
- **残留风险**：两边恰好在同一分钟内领到同一路径的卡，仍可能同时改，靠 git 推送时解决。

### 7. 同事视图

- 看板顶栏加「同事」，有同事数据时才出现，打开是一个只读整页：
  - 每人一块：名字、最后同步时间（超过 10 分钟标灰）、ateam 版本。
  - 进行中的需求：标题、进度（已完成 / 总卡数）。
  - 正在做的卡：卡号、标题、角色、谁在做、改哪些路径、做了多久。
  - 和你的卡路径重叠的，标出来。
- 点卡只显示详情（描述、验收标准、时间线），没有任何操作按钮。

### 8. 设置和命令

**看板「设置 → 多人协作」**：

| 设置 | 说明 |
|---|---|
| 同步看板 | 开关，默认关 |
| 同步名字 | 见第 4 节 |
| 远程 | 默认 `origin` |
| 同步用的仓库 | 只有多仓库模式下才有，默认第一个仓库 |
| 同步状态 | 最后一次推、拉成功的时间；失败时显示原因 |

这几项存在本机，不进看板文件：同步名字是每台机器各自的。

**命令行**：

- `ateam sync`：显示同步状态、同事列表和他们的最后同步时间。
- `ateam sync init [--name <名字>]`：开启并做第 9 节的迁移。
- `ateam sync off`：停止同步。不删除远程分支，并提示删除远程分支的 git 命令，由用户自己决定要不要删。

### 9. 迁移（已经把看板提交进 main 的项目，比如 sp）

`ateam sync init` 依次：

1. 检查：远程能连上、名字可用、本地看板能正常读。
2. 把当前看板推到 `ateam/<名字>`（第一次推送）。
3. 先显示一条在 main 上的改动，用户确认后才提交：
   - `git rm --cached -r .ateam/board.json .ateam/archive .ateam/demos`，本地文件保留；
   - `.ateam/.gitignore` 加上这几项。
4. 不自动推送 main，提示用户（或 leader）照常推送。

还要注意：

- 同事那边拉到这次提交后，git 会删掉他工作区里的这些文件，他本地就没有旧的「你的看板」了。这正是想要的效果。
- 如果他已经在用 ateam、有自己的数据，他的看板文件是他自己生成的，不在版本控制里，不受影响。
- 以前 main 历史里的看板提交保留，不改写历史。
- 没把看板提交进 git 的项目（默认情况）：`ateam sync init` 只做第 2 步。

### 10. 兼容和出错

| 情况 | 处理 |
|---|---|
| 断网、远程连不上 | 本地照常工作；状态里显示「上次同步 x 分钟前」，恢复后自动补推 |
| 没有权限、分支受保护 | 同步暂停，看板「待处理」出现一条「看板同步失败：<原因>」，给出要放行 `ateam/*` 的说明 |
| 名字被占用 | 同步不启动，提示改名 |
| 同事的格式版本更新 | 同事视图里这个人只显示「对方 ateam 版本较新，请升级后查看」，他的卡不参与路径检查 |
| 同事的格式版本更旧 | 照常读（只读必要字段） |
| 同步过程报错 | 不影响看板和派卡，只记日志、显示状态 |

### 11. 和现有功能的关系

- `ensureGitignore` 新增的忽略项只在开启同步后写入，不开启时行为不变。
- 设置（`board.json` 里的 `settings`）本来就随看板走，迁移后每人一份，各自生效。这和「每人各自管自己的团队」一致。
- token 用量、推送到手机、菜单栏都只看本机看板，不受影响。
- 卡片的「直接回复 worker」等所有写操作只对本机的卡有效。

## 留给实现时决定的

- 同步模块放在新文件 `src/sync.js`，server 负责定时调用和把状态交给看板。具体函数怎么拆由实现时决定。
- 同事视图的具体样式，沿用用量页的整页样式。
- 拉取频率、防抖时间、过期判断用常量，先不做成设置。

## 验证方式

- 按项目约定不写测试代码。实现时用 scratchpad 里的一次性探测脚本验证：临时目录、临时 bare 远程、两个克隆、临时端口。
  - 推拉；
  - 工作区不受影响；
  - 名字冲突；
  - 断网；
  - 跨人路径拦截；
  - 迁移步骤。
- 看板和同事视图交给用户手工核对，核对清单新增「多人协作」一组。
